### Navigation Principles

| Rule | Description |
|---|---|
| **Two layers, one panel** | Core Concepts (primary) + Form Archetypes (secondary) share the left panel |
| **Bidirectional linking** | Concept → "See how this builds forms" → Form; Form → "Generated by" → Concept |
| **No page reload** | Single-page app. Clicking anything updates the main content area |
| **Always visible** | Core Concepts always visible in left panel. Form Archetypes always visible below. |

## 2. Screen Hierarchy

### Screen States

```
STATE A: DEFAULT (Segmentation pre-selected)
├── Left panel: ✓ Segmentation (checked, highlighted), 3 others ○
│   Form Archetypes dimmed (lower opacity) until first concept click
├── Topbar: progress indicator "★ 1/4"
├── Main area: Segmentation detail view
│   └── Breadcrumb: Core Concepts > Segmentation
│   └── Content: problem → decision → mistake → exercise (with DAW prompt)
│       → canonical track (with arc visualization if Directionality)
│       → "How this builds forms"

STATE B: ANY CONCEPT DETAIL
├── Left panel: selected concept ✓, visited concepts ✓, unvisited ○
│   Form Archetypes: now fully visible
├── Topbar: progress indicator "★ 2/4" → "3/4" → "4/4"
├── Main area: Concept detail
│   └── Breadcrumb: Core Concepts > {Concept Name}
│   └── Progressive disclosure: initially shows only tagline + problem
│       Click "Show decision" → reveals decision + mistake
│       Click "Show exercise" → reveals exercise + DAW prompt + track

STATE B: CONCEPT DETAIL
├── Left panel: Same as HOME, but selected concept highlighted
├── Main area: Concept detail view
│   ├── Header: Concept name + tagline + Root Problem badge
│   ├── Section 1: Problem it solves + Composer Decision + Beginner Mistake
│   ├── Section 2: Exercise + Assessment
│   ├── Section 3: Canonical Track (timeline annotated by concept)
│   └── Section 4: "How this builds forms" — links to Form Archetypes

STATE C: FORM ARCHETYPE DETAIL
├── Left panel: Same as HOME, but selected form highlighted
│   └── Core Concepts that generate this form have a dot indicator
├── Main area: Form detail view
│   ├── Header: Form name + description
│   ├── ⚡ Generated by: [Segmentation] [Repetition] [Contrast] (clickable tags)
│   ├── Timeline: Section blocks with names + bars
│   ├── Section detail: Click section → see its function + which concept it uses
│   └── "Compare with other forms" — quick links to sibling forms

STATE D: COMPARE
├── Left panel: (dimmed, showing both modes)
├── Main area: Split view — Two forms side by side
│   └── Common concept annotations highlighted
```

### State Transitions

```
HOME ──click concept──→ CONCEPT DETAIL ──"see forms"──→ FORM DETAIL
                                ↑                          │
                                └────"which concepts"──────┘

HOME ──click form──→ FORM DETAIL ──click concept tag──→ CONCEPT DETAIL

Any state ──click left panel item──→ that item's detail
```

## 3. User Journey — First-Time Visitor

### Journey: "Producer with 16-bar loop, doesn't know what to do next"

**Step 1: Landing (0–15s)**

User sees:
```
[Segmentation]   [Repetition]   [Contrast]   [Directionality]
  "Where do I     "When do I      "When do I    "Where am I
   cut?"           return?"        change?"      going?"
```

Reaction: "I've had these exact questions. Let me click one."

---

**Step 2: First Concept — Segmentation (15s–3min)**

User clicks Segmentation.

Main area shows:

```
┌───────────────────────────────────────────────────────────┐
│  ★ SEGMENTATION                                          │
│  Root Problem: Organization of Musical Time               │
│                                                           │
│  ════════════════════════════════════════════════════════  │
│                                                           │
│  PROBLEM IT SOLVES                                        │
│  Material without boundaries is not perceived as form.    │
│  Segmentation turns a stream into architecture.           │
│                                                           │
│  COMPOSER DECISION                                        │
│  "Where does this idea end and another begin?"           │
│                                                           │
│  COMMON BEGINNER MISTAKE                                  │
│  An infinite loop without boundaries. Form = no form.    │
│                                                           │
│  ─── EXERCISE ───                                         │
│  Take one loop (16 bars).                                │
│  Do NOT change the material.                              │
│  Only place boundaries: intro / core / outro.             │
│  Minimum 3 sections. (Try it →)                           │
│                                                           │
│  ─── CANONICAL TRACK ───                                  │
│  Daft Punk — Around the World (1997)                      │
│  [Intro ┃ Core Groove ┃ Filter Sweep ┃ Core ┃ Outro]     │
│   Each line = a boundary                                  │
│                                                           │
│  ─── HOW THIS BUILDS FORMS ───                            │
│  Segmentation → [Verse-Chorus] [Club Arc] [Rondo]        │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

Reaction: "I can do that exercise right now. And I know that Daft Punk track."

---

**Step 3: See how Segmentation builds forms (3min–4min)**

User clicks "Verse-Chorus" link in "How this builds forms."

Main area switches to Form Archetype view:

```
┌───────────────────────────────────────────────────────────┐
│  Verse-Chorus Song Form                                   │
│  ⚡ Generated by: [Segmentation] [Repetition] [Contrast] │
│                                                           │
│  Classical pop structure: verse → chorus → bridge → ...  │
│                                                           │
│  [Intro┃Verse 1┃Pre-chorus┃Chorus┃Verse 2┃Bridge┃Chorus]  │
│        ▲                                                   │
│        └ Segmentation: each boundary marked by harmony     │
│          or energy change                                  │
│                                                           │
│  Click a section to see which concept powers it:          │
│  │ Pre-chorus → Contrast (builds tension before chorus)   │
│  │ Chorus → Repetition (returns 3 times)                  │
│  │ Bridge → Contrast (change of perspective)              │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

Reaction: "I see — Segmentation is what makes the song have verses and choruses in the first place. Without it, it's just a wall of sound."

---

**Step 4: Explore another concept — Repetition (4min–8min)**

User navigates back to left panel, clicks Repetition.

Main area shows Repetition detail with:
- Canonical track: Daft Punk — Around the World (same track! different concept lens)
- "How this builds forms" → links to same forms but showing Repetition's role

Reaction: "The same track teaches me two different things? This is efficient."

---

**Step 5: Combine (8min–best guess)**

User has now seen 2–3 concepts. At any point they can:
- Scroll down the left panel to Form Archetypes and click one
- See the "Generated by" tags: "Oh, Verse-Chorus uses 3 of the 4 concepts I just learned"
- Click a concept tag to review
- Click another form to see how the same concepts power a completely different genre

---

**Step 6: Exit after 30 minutes**

User leaves with:

1. **4 questions in their head:** Where to cut? When to return? When to change? Where am I going?
2. **A concrete track memory** for each question
3. **An exercise** they can do tonight
4. **Understanding that** verse-chorus, club arc, and rondo are just different combinations of the same 4 tools

**Key insight:** The user does NOT leave knowing "4 form archetypes." They leave knowing "I have 4 tools. I can build any form."

## 4. Mapping: Core Concepts ↔ Form Archetypes

### Concept-to-Form Matrix

| Core Concept | Verse-Chorus | Club Arc | Rondo | Process Minimal |
|---|---|---|---|---|
| **Segmentation** | Essential | Essential | Essential | Essential |
| **Repetition** | Essential | Secondary | Essential | Essential |
| **Contrast** | Essential | Essential | Essential | Minimal |
| **Directionality** | Secondary | Essential | Secondary | Essential |

**Legend:**
- Essential = the form cannot exist without this concept
- Secondary = the form uses this but could survive without it
- Minimal = the form deliberately minimizes this concept

### Form-to-Concept Details

**Verse-Chorus (Pop)**
→ Segmentation (verse/chorus/bridge boundaries)
→ Repetition (chorus returns 3x, hook repetition)
→ Contrast (verse narrative vs chorus hook, bridge modulation)

**Club Arc (Electronic)**
→ Segmentation (intro/groove/build/drop/breakdown/outro)
→ Contrast (low-energy intro vs full drop, breakdown reset)
→ Directionality (energy build-up → peak → release arc)

**Rondo (Classical)**
→ Segmentation (A/B/A/C/A — clear section borders)
→ Repetition (A refrain returns between episodes)
→ Contrast (B and C episodes in different keys/textures)

**Process-Based Minimal (Contemporary)**
→ Segmentation (soft, gradual section changes)
→ Repetition (cellular repetition as foundation)
→ Directionality (accumulation → dissolution arc)

### Concept Dominance by Form Type

| Form | Dominant Concept |
|---|---|
| Verse-Chorus | Repetition (form is defined by return) |
| Club Arc | Directionality (form is defined by arc) |
| Rondo | Segmentation (form is defined by clear returns) |
| Process Minimal | Repetition (form is defined by cellular process) |

### UI Element Specs

| Element | Type | Behavior |
|---|---|---|
| **Topbar brand** | Text + icon | Always visible. No interaction. |
| **Topbar progress indicator** | Badge | Shows "★ 1/4" → "4/4" based on visited concepts. Updates in real time as user visits each concept. Resets on page reload. |
| **Topbar "Learn step guide"** | Button | Toggles step-by-step concept guide (optional) |
| **Breadcrumb** | Text in main area header | Always visible. Format: "Core Concepts > {Current Name}". Clickable segments: "Core Concepts" = reset to Segmentation default. |
| **Concept card** | Left panel clickable | Shows ✓ when visited, ○ when unvisited. Highlighted when selected. Lower opacity = not yet visited. |
| **Form card** | Left panel clickable | Below Concepts visually. Shows generation formula. Initially dimmed (opacity 0.5) until first concept is clicked, then full opacity with a subtle animation. |
| **Main content** | Dynamic panel | Changes based on selection. Starts with Segmentation detail on page load. Contains: concept detail, form detail, or compare. |
| **"Generated by" tags** | Clickable badges | Click a concept tag → navigate to that concept detail. |
| **"How this builds forms"** | Clickable links | At bottom of concept detail. Click a form name → navigate to that form detail. |

### Content Hierarchy per View

**Concept Detail View (top to bottom):**
1. Breadcrumb: `Core Concepts > {Concept Name}`
2. ★ Concept name + tagline
3. Root Problem badge
4. Problem it solves (1 paragraph) — visible on load
5. [Show decision] button (toggle) → reveals:
   a. Composer Decision (1 line, in quotation marks)
   b. Common Beginner Mistake (1 paragraph)
6. [Show exercise] button (toggle) → reveals:
   a. Exercise (numbered steps)
   b. Assessment (yes/no criterion)
   c. ▶ **DAW prompt:** 1 concrete sentence instructing the user to try this on their own unfinished track
7. Canonical Track (name + mini timeline with concept annotations)
   *(If concept = Directionality: timeline includes energy arc — bars sloping up → peak → down)*
8. "How this builds forms" → clickable form names

**Form Archetype Detail View (top to bottom):**
1. Form name + description
2. ⚡ Generated by: [concept tags]
3. Timeline with sections (clickable)
4. Clicked section detail: "This section uses [Segmentation] because..."
5. "See which concepts power this" → clickable concept names
6. Examples (existing data from v1.0)
7. "Compare with:" links to other 3 forms

## 6. Implementation Phasing

### Phase 1 (Core Data Model)
- Rewrite `app.js` data: split into `coreConcepts[]` and `formArchetypes[]`
- Add `generatedBy: ["segmentation", "repetition", ...]` to each form
- Add `demoTrack` and `buildsForms` to each concept

### Phase 2 (Navigation)
- Replace left panel: 4 concept cards + 4 form cards
- Remove filters (genre/form/tempo/difficulty)
- Handle click → state change → render logic

### Phase 3 (Main Content)
- `renderConceptDetail(concept)` — full concept view with problem/decision/mistake/exercise/track
- `renderFormDetail(form)` — form view with "Generated by" tags
- `renderCanonicalTrack(concept)` — timeline annotated by concept

### Phase 4 (Polish)
- Color system for concepts
- "How this builds forms" / "See which concepts power this" bidirectional links
- Exercise display
- Compare mode (optional)

## 7. Decision Record

| Decision | Rationale |
|---|---|
| **Concepts primary, forms secondary** | Pedagogical priority: teach tools before templates |
| **Both visible in left panel simultaneously** | User can explore without losing context |
| **Concepts above forms in left panel** | Visual hierarchy reinforces learning priority |
| **Segmentation selected on page load** | Removes first-visit paralysis. "Start here" is explicit. |
| **Progressive disclosure (Show decision / Show exercise)** | Prevents information overload. Each block revealed on demand. |
| **DAW prompt after every exercise** | Bridges gap between theory and action. Critical for transfer. |
| **Directionality: energy arc visualization** | Directionality cannot be taught with text alone. Visual arc is essential. |
| **Breadcrumbs** | Prevents "lost in the maze" when navigating concept↔form. |
| **Progress indicator (★ 1/4 → 4/4)** | Creates motivation loop. Sense of completion drives continued use. |
| **Forms initially dimmed** | Prevents split attention on first visit. Forms reveal after concept exploration begins. |
| **"Generated by" tags are clickable** | Creates bidirectional navigation: concept → form → concept |
| **Same canonical track can appear under multiple concepts** | Shows that a single track demonstrates multiple tools |
| **No filters** | 4 concepts + 4 forms = 8 items. No search needed. |
| **v1.0 data preserved in formArchetypes[]** | No data lost. Sections, examples, sources retained. |
| **Sources panel hidden in Core view** | Academic sources belong to Extended layer, not beginner flow |
